# 编码文件的完整工作流

用户要求持续补齐 Git 客户端功能，直到此前列出的功能完成。本增量解决已经实现的编码补丁导入与普通 Git 操作之间的数据口径断层；不把普通暂存写入原始 UTF-16 字节当作成功。

## 必须满足的行为

- ODB / index 保存 Git 规范内容，工作树保存属性指定的编码；Stage、状态、Diff、部分操作与补丁导出采用相同转换顺序。
- Git add 的 safecrlf / encoding roundtrip 策略与纯 git apply 的策略分别实现，保留现有真实 Git oracle 的行为。
- 检出必须使用目标树的属性，先验证所有目标输出；只把规范内容等价于 index 的干净文件临时正规化，真实用户修改不能被安全检查误判或覆盖。
- 引用仍由原业务操作在检出成功后发布。中断恢复固定所属工作树、HEAD / index / 属性 / 配置及原始字节，不能重新执行可变过滤器；外部编辑保持原位并明确拒绝覆盖。
- 未接入转换事务的原生写点必须在写入之前拒绝受影响的编码文件，最终覆盖普通 checkout / discard / reset、merge / pull / rebase、stash、冲突、clone 和关联 Worktree / 子模块路径。
- 复用已有 UTF-8 / UTF-16 / UTF-32 严格 codec 与经过真实 Git 对照的 Unix legacy codec。未知编码与自定义过滤器明确报错；不增加 system Git / Bash 生产执行路径。
- 普通无编码文件保留现有原生快路径，不能把补丁整批预算变成全仓库暂存大小限制。编码转换使用显式 raw / canonical 字节预算，超限保留原文件与索引，不截断。
- 保留普通文件 Git 模式、字面路径及安全写入规则；不得跟随符号链接，也不能通过覆盖一个路径破坏其他硬链接。

## 验证与执行边界

以隔离仓库中系统 Git 的 add / checkout / diff / apply 结果为 oracle，生产实现仍使用 Rust / libgit2 与原生转换库。验证 UTF-16 导入后普通暂存、属性随分支切换、无损失败、部分操作、并发变化和中断恢复；原生 UI 另行验证用户回路。

当前已经通过的整合快照为 584 项 Rust 测试、14 项 Python 测试及严格 Clippy / 格式检查。本增量之后必须重新验证，不能复用该数量作为最终结果。
